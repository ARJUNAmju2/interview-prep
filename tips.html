🎤 "Tell Me About Yourself" (60-second script)

Template: "I'm [Name], a .NET Full Stack Developer with 4.7 years of experience. I primarily work with C#, ASP.NET Core MVC, Web API, SQL Server, and JavaScript. In my current role at [Company], I've been working on [brief project description — e.g., 'an enterprise ERP system handling order management and inventory']. I've been involved in designing RESTful APIs, implementing Repository pattern with EF Core, and optimizing SQL queries for performance. I follow SOLID principles and use Dependency Injection extensively. I'm looking for a role where I can take on more architectural responsibilities and work with modern .NET technologies."
Tips: Keep it under 60 seconds. Cover: Who you are → Tech stack → Current project (1 line) → Key achievements → Why looking for change.

🎯 Most Asked Topics (4.7 Yrs Exp)

Abstract class vs Interface — Asked in EVERY interview. Know when to use which with real project examples. HOT
virtual/override vs new — Favorite interviewer trap. Be ready to explain code output. HOT
Value Type vs Reference Type — Explain Stack/Heap with memory diagram. HOT
Dependency Injection using Interfaces — Show how you use it in ASP.NET Core projects. HOT
IEnumerable vs IQueryable — Explain WHERE filtering happens (client vs server). IMP
Composition vs Inheritance — Say "Favor composition over inheritance" and explain why. IMP
SOLID Principles — At 4.7 yrs, they expect you to know all 5 with examples. HOT
async/await — Explain thread pool, non-blocking I/O, when NOT to use async. IMP
Boxing/Unboxing — Explain performance impact and how Generics solve it.
Delegate, Func, Action, Lambda — Know the difference and real usage in LINQ.

⚡ Key Rules for 4.7 Yrs Experience

Don't just say WHAT — Always explain WHEN and WHY you'd use it in real projects.
Always offer to write code — Shows confidence. Even pseudo-code on whiteboard helps.
Link to your project — "In my project, I used Repository pattern because..." wins points.
Know trade-offs — "Abstract class gives shared code, Interface gives flexibility" — show you think.
Admit what you don't know — "I haven't used that, but I think it works like..." is better than faking.

📋 Interview Day Checklist

OOPs — 4 pillars, Abstract vs Interface, Polymorphism (virtual/override/new)
C# — Value/Ref types, Generics, async/await, LINQ, Exception handling
ASP.NET Core — Middleware, DI, Filters, Routing, Model Binding
SQL — Joins, Indexes, Stored Procedures, Query optimization
Design Patterns — Singleton, Repository, Factory, Strategy (at minimum)
Project — Be ready to explain architecture, challenges faced, and how you solved them

🎤 HR Questions (Asked in EVERY interview)

"What is your daily workflow?"
"We follow Agile/Scrum with 2-week sprints. Daily stand-up (15 min), sprint planning, retrospective. I pick tasks from Jira/Azure DevOps board, develop, create PR for code review, then deploy after approval. I coordinate with QA for testing and DBA for database changes."
"Why are you looking for a change?"
"I've learned a lot in my current role, but I'm looking for more challenging work with modern technologies. I want to work on larger-scale systems, contribute to architectural decisions, and grow into a senior/lead role. Your company's tech stack and project scale align with my career goals."
(Never badmouth current company!)
"What is your expected CTC/salary?"
Research market rate for 4.7 yrs .NET (typically 30-50% hike). Say: "Based on my experience and market standards, I'm expecting [X] LPA. However, I'm flexible and open to discussion based on the overall package and growth opportunities."
"Where do you see yourself in 5 years?"
"I see myself as a Technical Lead or Solution Architect, designing systems end-to-end. I want to mentor junior developers, make architectural decisions, and contribute to the technical direction of the team. I'm also interested in cloud technologies (Azure/AWS) and microservices architecture."
"Do you have any questions for us?" (Always ask 2-3!)
1. "What does the tech stack look like for this role? Any plans to adopt newer technologies?"
2. "How is the team structured? How many developers, and what's the code review process?"
3. "What does a typical project timeline look like? Agile sprints?"
(Never ask about salary/leave in first round. Shows you care about work, not just money.)

🚫 Common Mistakes to Avoid

Don't memorize definitions — Understand concepts. Interviewers ask follow-ups.
Don't say "I used it but forgot" — Either know it or say you haven't used it.
Don't skip basics — Even at 4.7 yrs, they ask "What is polymorphism?" — answer confidently.
Don't give one-word answers — Elaborate with examples. Show depth.
Don't panic on coding — Think aloud, explain approach first, then code.
