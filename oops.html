OOPs Interview Questions

1 Q1. What is Object-Oriented Programming? ▼ 
OOP is a programming paradigm that organizes code around OBJECTS (data + behavior)
rather than functions and logic.

Key idea: Model real-world entities as objects in code.

Example:
- Real world: A Car has properties (color, speed) and behaviors (start, stop)
- In code: Car class with properties and methods

public class Car
{
    // Properties (data)
    public string Color { get; set; }
    public int Speed { get; set; }
    
    // Methods (behavior)
    public void Start() { Console.WriteLine("Car started"); }
    public void Stop() { Console.WriteLine("Car stopped"); }
}

// Object (instance of class)
Car myCar = new Car();
myCar.Color = "Red";
myCar.Start();

OOP focuses on:
- What objects are needed (not what functions)
- How objects interact with each other
- Hiding complexity and exposing only necessary parts
2 Q2. What are the 4 pillars of OOPs? ▼ 
1. ENCAPSULATION:
   - Wrapping data and methods together in a class
   - Hiding internal details, exposing only necessary interface
   - Using access modifiers (private, public, protected)
   - Example: Private fields with public properties (get/set)

2. INHERITANCE:
   - Creating new class from existing class
   - Child class inherits properties and methods of parent
   - Promotes code reusability
   - Example: Dog : Animal (Dog inherits from Animal)

3. POLYMORPHISM:
   - One interface, multiple implementations
   - Same method behaves differently based on object
   - Compile-time (overloading) and Runtime (overriding)
   - Example: Shape.Draw() ? Circle draws circle, Square draws square

4. ABSTRACTION:
   - Hiding complex implementation, showing only essential features
   - Using abstract classes and interfaces
   - Focus on WHAT an object does, not HOW
   - Example: You drive a car without knowing engine internals
3 Q3. What is the difference between Procedural vs OOP? ▼ 
PROCEDURAL PROGRAMMING:
- Organized around functions/procedures
- Data and functions are separate
- Top-down approach
- No access control on data
- Hard to maintain for large programs
- Examples: C, Pascal, BASIC

OOP:
- Organized around objects (data + behavior)
- Data and methods bundled together
- Bottom-up approach
- Access modifiers protect data
- Easy to maintain and extend
- Examples: C#, Java, Python, C++

| Feature        | Procedural         | OOP                  |
|----------------|--------------------|--------------------- |
| Focus          | Functions          | Objects              |
| Data           | Exposed            | Encapsulated         |
| Reusability    | Limited            | High (Inheritance)   |
| Security       | Less               | More (Access control)|
| Maintenance    | Difficult          | Easier               |
| Real-world     | Poor mapping       | Good mapping         |
4 Q4. What is a Class and Object? ▼ 
CLASS:
- A blueprint/template for creating objects
- Defines properties (data) and methods (behavior)
- Exists in code (compile-time concept)
- No memory allocated until object is created
- Like an architectural plan of a house

OBJECT:
- An instance of a class
- Actual entity created in memory at runtime
- Has actual values for properties
- Like the actual house built from the plan

Example:
// Class (blueprint)
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Salary { get; set; }
    
    public void DisplayInfo()
    {
        Console.WriteLine($"{Id}: {Name} - {Salary:C}");
    }
}

// Objects (instances)
Employee emp1 = new Employee { Id = 1, Name = "John", Salary = 50000 };
Employee emp2 = new Employee { Id = 2, Name = "Jane", Salary = 60000 };

emp1.DisplayInfo();  // 1: John - $50,000
emp2.DisplayInfo();  // 2: Jane - $60,000

// emp1 and emp2 are different objects of same class
// They share the same structure but have different data

6 Q6. What is a Constructor? ▼ 
A Constructor is a special method that is automatically called when an object 
is created. It initializes the object's state.

Rules:
- Same name as the class
- No return type (not even void)
- Called automatically with 'new' keyword
- Can be overloaded
- If no constructor defined, compiler provides default

Example:
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    // Default constructor
    public Employee()
    {
        Id = 0;
        Name = "Unknown";
    }
    
    // Parameterized constructor
    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
    }
}

// Usage
Employee emp1 = new Employee();           // Calls default constructor
Employee emp2 = new Employee(1, "John");  // Calls parameterized constructor

Purpose:
- Initialize object with default/specific values
- Allocate resources
- Enforce required data at creation time
- Dependency injection (in ASP.NET Core)
7 Q7. What are types of Constructors? ▼ 
1. DEFAULT CONSTRUCTOR:
   - No parameters
   - Compiler provides one if you don't write any constructor
   
   public Employee() { }

2. PARAMETERIZED CONSTRUCTOR:
   - Takes parameters to initialize object
   
   public Employee(int id, string name)
   {
       Id = id;
       Name = name;
   }

3. COPY CONSTRUCTOR:
   - Creates object by copying another object
   - C# doesn't have built-in copy constructor (unlike C++)
   
   public Employee(Employee other)
   {
       Id = other.Id;
       Name = other.Name;
   }

4. STATIC CONSTRUCTOR:
   - Initializes static members
   - Called only ONCE (first time class is used)
   - No access modifier, no parameters
   - Cannot be called directly
   
   static Employee()
   {
       // Initialize static fields
       CompanyName = "TechCorp";
   }

5. PRIVATE CONSTRUCTOR:
   - Cannot create object from outside the class
   - Used in Singleton pattern
   - Used when class has only static members
   
   private Employee() { }
   
   // Singleton usage
   public class Singleton
   {
       private static Singleton _instance;
       private Singleton() { }  // Private!
       
       public static Singleton Instance
       {
           get
           {
               if (_instance == null)
                   _instance = new Singleton();
               return _instance;
           }
       }
   }
8 Q8. What is Constructor Overloading? ▼ 
Constructor Overloading means having multiple constructors in the same class 
with different parameter lists.

Example:
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string Category { get; set; }
    
    // Constructor 1: No parameters
    public Product()
    {
        Name = "Unknown";
        Price = 0;
    }
    
    // Constructor 2: Name only
    public Product(string name)
    {
        Name = name;
        Price = 0;
    }
    
    // Constructor 3: Name and Price
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }
    
    // Constructor 4: All parameters
    public Product(int id, string name, decimal price, string category)
    {
        Id = id;
        Name = name;
        Price = price;
        Category = category;
    }
}

// Usage - different ways to create object
var p1 = new Product();
var p2 = new Product("Phone");
var p3 = new Product("Phone", 999);
var p4 = new Product(1, "Phone", 999, "Electronics");

Rules:
- Same name (class name)
- Different number or type of parameters
- Compiler picks the right one based on arguments passed
9 Q9. What is Constructor Chaining (this/base)? ▼ 
Constructor Chaining means one constructor calling another constructor 
using 'this' (same class) or 'base' (parent class).

Using 'this' (same class):
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Department { get; set; }
    
    public Employee() : this(0, "Unknown", "General")
    {
        // Calls the 3-parameter constructor first
    }
    
    public Employee(int id, string name) : this(id, name, "General")
    {
        // Calls the 3-parameter constructor first
    }
    
    public Employee(int id, string name, string department)
    {
        Id = id;
        Name = name;
        Department = department;
    }
}

Using 'base' (parent class):
public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
    
    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

public class Employee : Person
{
    public decimal Salary { get; set; }
    
    public Employee(string name, int age, decimal salary) : base(name, age)
    {
        // Calls Person(name, age) first, then sets Salary
        Salary = salary;
    }
}

Benefits:
- Avoid code duplication
- Single point of initialization logic
- Cleaner code
10 Q10. What is a Destructor/Finalizer in C#? ▼ 
A Destructor (Finalizer) is called by the Garbage Collector before an object 
is destroyed. Used to release unmanaged resources.

Syntax:
public class FileHandler
{
    private IntPtr fileHandle;
    
    public FileHandler(string path)
    {
        fileHandle = OpenFile(path);  // Unmanaged resource
    }
    
    // Destructor/Finalizer
    ~FileHandler()
    {
        // Cleanup unmanaged resources
        CloseFile(fileHandle);
        Console.WriteLine("Destructor called - resources released");
    }
}

Rules:
- Prefix with ~ (tilde) + class name
- No access modifier
- No parameters
- No return type
- Cannot be called directly (GC calls it)
- Only ONE destructor per class
- Cannot be overloaded

Important:
- You CANNOT predict when GC will call the destructor
- Prefer IDisposable pattern over destructors
- Destructors add overhead (objects go to finalization queue)

Better approach - IDisposable:
public class FileHandler : IDisposable
{
    private bool _disposed = false;
    
    public void Dispose()
    {
        if (!_disposed)
        {
            // Release resources
            _disposed = true;
        }
        GC.SuppressFinalize(this);  // Skip finalizer
    }
    
    ~FileHandler()
    {
        Dispose();
    }
}

// Usage
using (var handler = new FileHandler("file.txt"))
{
    // Use handler
}  // Dispose called automatically
11 Q11. What is the difference between Struct and Class? ▼ 
| Feature          | Struct (Value Type)      | Class (Reference Type)   |
|------------------|--------------------------|--------------------------|
| Storage          | Stack                    | Heap                     |
| Type             | Value type               | Reference type           |
| Inheritance      | Cannot inherit           | Can inherit              |
| Default value    | Cannot be null           | Can be null              |
| Constructor      | Cannot have parameterless| Can have parameterless   |
|                  | (before C# 10)           |                          |
| Destructor       | Cannot have              | Can have                 |
| Performance      | Faster (no GC)           | Slower (GC overhead)     |
| Assignment       | Copies entire value      | Copies reference         |
| Sealed           | Always sealed            | Can be sealed or not     |
| Interface        | Can implement            | Can implement            |

When to use Struct:
- Small data (< 16 bytes)
- Immutable data
- Short-lived objects
- No inheritance needed
- Examples: Point, Color, DateTime, int, decimal

When to use Class:
- Complex objects
- Need inheritance
- Large data
- Need null reference
- Long-lived objects
- Examples: Employee, Order, DbContext

Example:
struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

Point p1 = new Point { X = 1, Y = 2 };
Point p2 = p1;  // COPIES the value
p2.X = 10;
// p1.X is still 1 (independent copy)

class Employee
{
    public string Name { get; set; }
}

Employee e1 = new Employee { Name = "John" };
Employee e2 = e1;  // COPIES the reference (both point to same object)
e2.Name = "Jane";
// e1.Name is now "Jane" (same object!)
12 Q12. What is a Static class? ▼ 
A Static class is a class that cannot be instantiated and can only contain 
static members.

Rules:
- Cannot create objects (no 'new')
- Cannot be inherited
- Can only have static members
- Sealed implicitly
- No instance constructor (only static constructor)

Example:
public static class MathHelper
{
    public static double PI = 3.14159;
    
    public static int Add(int a, int b) => a + b;
    public static int Multiply(int a, int b) => a * b;
    public static double CircleArea(double radius) => PI * radius * radius;
}

// Usage - no 'new' needed
int sum = MathHelper.Add(5, 3);
double area = MathHelper.CircleArea(10);

Use cases:
- Utility/Helper classes (StringHelper, MathHelper)
- Extension methods container
- Constants and configuration
- Stateless operations

Common .NET static classes:
- Math.Abs(), Math.Max()
- Console.WriteLine()
- File.ReadAllText()
- Convert.ToInt32()
13 Q13. What is a Partial class? ▼ 
A Partial class allows splitting a single class definition across multiple files.
All parts are combined at compile time.

Keyword: partial

File 1 - Employee.cs:
public partial class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
}

File 2 - Employee.Methods.cs:
public partial class Employee
{
    public void DisplayInfo()
    {
        Console.WriteLine($"{Id}: {Name} ({Email})");
    }
    
    public bool IsValid()
    {
        return !string.IsNullOrEmpty(Name) && !string.IsNullOrEmpty(Email);
    }
}

// At compile time, both files merge into ONE class

Use cases:
- Large classes split for readability
- Auto-generated code (EF Core models, WinForms designer)
- Multiple developers working on same class
- Separating concerns (properties in one file, methods in another)

Rules:
- All parts must use 'partial' keyword
- All parts must be in same namespace and assembly
- All parts must have same accessibility (public, internal)
- If any part is abstract/sealed, entire class is abstract/sealed
14 Q14. What is a Sealed class? ▼ 
A Sealed class is a class that CANNOT be inherited. No other class can 
derive from it.

Keyword: sealed

public sealed class StringHelper
{
    public static string Capitalize(string input)
    {
        return char.ToUpper(input[0]) + input.Substring(1);
    }
}

// This will cause COMPILE ERROR:
public class ExtendedHelper : StringHelper  // ERROR! Cannot inherit sealed class
{
}

Sealed method (prevent further overriding):
public class Animal
{
    public virtual void Speak() { }
}

public class Dog : Animal
{
    public sealed override void Speak()  // Can be overridden here but sealed
    {
        Console.WriteLine("Bark");
    }
}

public class GoldenRetriever : Dog
{
    // ERROR! Cannot override sealed method
    public override void Speak() { }  // Compile error!
}

Why use sealed:
- Security: Prevent modification of critical classes
- Performance: JIT can optimize (no virtual dispatch needed)
- Design: Class not designed for inheritance
- Framework classes: String, DateTime are sealed

.NET sealed classes: String, StringBuilder, DateTime, Math

15 Q15. What is Encapsulation? ▼ 
Encapsulation is wrapping data (fields) and methods that operate on that data 
into a single unit (class), and restricting direct access to internal details.

"Hide the HOW, expose the WHAT"

Without Encapsulation (bad):
public class BankAccount
{
    public decimal Balance;  // Anyone can directly modify!
}

var account = new BankAccount();
account.Balance = -5000;  // Invalid! But no protection

With Encapsulation (good):
public class BankAccount
{
    private decimal _balance;  // Hidden from outside
    
    public decimal Balance => _balance;  // Read-only access
    
    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive");
        _balance += amount;
    }
    
    public void Withdraw(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive");
        if (amount > _balance)
            throw new InvalidOperationException("Insufficient funds");
        _balance -= amount;
    }
}

// Now balance is protected
var account = new BankAccount();
account.Deposit(1000);    // Valid
account.Withdraw(500);    // Valid
account.Withdraw(2000);   // Exception! Insufficient funds
// account._balance = -5000;  // Compile error! Private

Benefits:
- Data protection (validation before modification)
- Hide complexity
- Control access
- Easy to change internal implementation without affecting users
- Maintainability
16 Q16. What are Access Modifiers? ▼ 
Access Modifiers control the visibility/accessibility of classes, methods, 
and properties.

6 Access Modifiers in C#:

1. public:
   - Accessible from ANYWHERE (no restriction)
   - Any class, any assembly
   
2. private:
   - Accessible ONLY within the same class
   - Most restrictive
   - Default for class members
   
3. protected:
   - Accessible within same class AND derived classes
   - Not accessible from outside (non-derived)
   
4. internal:
   - Accessible within the SAME ASSEMBLY (project)
   - Not accessible from other projects
   - Default for classes
   
5. protected internal:
   - Accessible within same assembly OR derived classes (even in other assembly)
   - Union of protected and internal
   
6. private protected (C# 7.2):
   - Accessible within same class OR derived classes in SAME ASSEMBLY
   - Intersection of private and protected

Example:
public class Employee
{
    public string Name { get; set; }           // Anywhere
    private decimal _salary;                    // Only this class
    protected int EmployeeLevel;               // This class + derived
    internal string Department;                // Same assembly
    protected internal string Branch;          // Same assembly OR derived
    private protected string SecretCode;       // Derived in same assembly only
}
17 Q17. What is the difference between all access modifiers? ▼ 
| Modifier           | Same Class | Derived (same) | Same Assembly | Derived (other) | Other Assembly |
|--------------------|------------|----------------|---------------|-----------------|----------------|
| public             | YES        | YES            | YES           | YES             | YES            |
| private            | YES        | NO             | NO            | NO              | NO             |
| protected          | YES        | YES            | NO            | YES             | NO             |
| internal           | YES        | YES            | YES           | NO              | NO             |
| protected internal | YES        | YES            | YES           | YES             | NO             |
| private protected  | YES        | YES            | NO            | NO              | NO             |

Most commonly used:
- public: API methods, properties exposed to consumers
- private: Internal fields, helper methods
- protected: Members needed by child classes
- internal: Classes/methods shared within project but not exposed outside

Default access:
- Class: internal
- Class members: private
- Interface members: public (implicitly)
- Struct members: private
18 Q18. What are Properties (get/set)? ▼ 
Properties provide controlled access to private fields. They look like fields 
from outside but have getter/setter logic internally.

Full property:
public class Employee
{
    private string _name;
    private int _age;
    
    public string Name
    {
        get { return _name; }
        set
        {
            if (string.IsNullOrEmpty(value))
                throw new ArgumentException("Name cannot be empty");
            _name = value;
        }
    }
    
    public int Age
    {
        get { return _age; }
        set
        {
            if (value < 18 || value > 65)
                throw new ArgumentException("Age must be 18-65");
            _age = value;
        }
    }
}

Auto-implemented property:
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

Read-only property:
public string FullName => $"{FirstName} {LastName}";  // Expression body
public DateTime CreatedDate { get; } = DateTime.Now;  // Set only in constructor

Property with different access:
public string Name { get; private set; }  // Public read, private write

Init-only property (C# 9):
public string Name { get; init; }  // Can only be set during initialization
var emp = new Employee { Name = "John" };  // OK
emp.Name = "Jane";  // ERROR after initialization
19 Q19. What is the difference between Field and Property? ▼ 
FIELD:
- Variable declared directly in class
- No get/set logic
- Usually private
- No validation possible
- Direct memory access

private string _name;
private int _age;

PROPERTY:
- Wrapper around field with get/set accessors
- Can have validation logic
- Usually public
- Can be read-only or write-only
- Can trigger events on change

public string Name
{
    get => _name;
    set => _name = value ?? throw new ArgumentNullException();
}

| Feature      | Field              | Property             |
|--------------|--------------------|----------------------|
| Access       | Direct             | Through get/set      |
| Validation   | No                 | Yes                  |
| Visibility   | Usually private    | Usually public       |
| Data binding | Not supported      | Supported (WPF/MVC) |
| Interface    | Cannot be in       | Can be in interface  |
| Debugging    | No breakpoint      | Can set breakpoint   |
| Serialization| May not serialize  | Serializes properly  |

Best Practice: 
- Fields should be PRIVATE
- Expose data through PROPERTIES
- Even for simple cases, use auto-properties (future-proof)
20 Q20. What is Auto-implemented Property? ▼ 
Auto-implemented properties let you declare properties without explicitly 
defining a backing field. Compiler creates the hidden field automatically.

// Auto-implemented (compiler creates hidden backing field)
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Salary { get; set; }
    public DateTime HireDate { get; set; } = DateTime.Now;  // With default
}

// Equivalent full implementation (what compiler generates):
public class Employee
{
    private int _id;
    private string _name;
    
    public int Id
    {
        get { return _id; }
        set { _id = value; }
    }
    
    public string Name
    {
        get { return _name; }
        set { _name = value; }
    }
}

When to use auto-property:
- No validation needed
- Simple get/set
- Most common scenario

When to use full property:
- Need validation in setter
- Need to raise events (INotifyPropertyChanged)
- Need computed values in getter
- Need logging or side effects
21 Q21. What is Read-only vs Write-only Property? ▼ 
READ-ONLY PROPERTY (only getter):
public class Circle
{
    public double Radius { get; }
    
    // Computed read-only
    public double Area => Math.PI * Radius * Radius;
    
    // Set only via constructor
    public Circle(double radius)
    {
        Radius = radius;
    }
}

var c = new Circle(5);
double area = c.Area;  // OK - can read
// c.Radius = 10;      // ERROR - cannot set

WRITE-ONLY PROPERTY (only setter - rare):
public class Logger
{
    private string _password;
    
    public string Password
    {
        set { _password = HashPassword(value); }
        // No getter - cannot read password back
    }
}

var logger = new Logger();
logger.Password = "secret123";  // OK - can set
// var pwd = logger.Password;   // ERROR - cannot read

Common read-only patterns:
public string FullName => $"{FirstName} {LastName}";     // Computed
public int Age => DateTime.Now.Year - BirthYear;         // Calculated
public bool IsAdult => Age >= 18;                        // Derived
public static DateTime Now => DateTime.UtcNow;           // Static
22 Q22. What is the readonly keyword vs const? ▼ 
CONST:
- Compile-time constant
- Must be assigned at declaration
- Implicitly static
- Only primitive types and string
- Value embedded in IL code
- Cannot change ever

const double PI = 3.14159;
const string AppName = "MyApp";
const int MaxRetries = 3;
// const DateTime Now = DateTime.Now;  // ERROR! Not compile-time

READONLY:
- Runtime constant
- Can be assigned at declaration OR in constructor
- Can be instance or static
- Any type (including objects)
- Value resolved at runtime

public class Config
{
    public readonly string ConnectionString;
    public readonly DateTime CreatedAt = DateTime.Now;
    public static readonly int MaxUsers = GetMaxFromConfig();
    
    public Config(string connStr)
    {
        ConnectionString = connStr;  // Set in constructor - OK
    }
    
    public void Update()
    {
        // ConnectionString = "new";  // ERROR! Cannot change after constructor
    }
}

Comparison:
| Feature        | const              | readonly             |
|----------------|--------------------|----------------------|
| Assigned       | Declaration only   | Declaration/Constructor |
| Time           | Compile-time       | Runtime              |
| Static         | Always (implicit)  | Can be instance      |
| Types          | Primitives, string | Any type             |
| Performance    | Slightly faster    | Normal               |
| Versioning     | Dangerous*         | Safe                 |

*Versioning issue with const:
If Assembly A has: public const int Version = 1;
And Assembly B uses it: var v = A.Version;
If A changes to Version = 2 and recompiles, B still has 1 (embedded at compile time)
B must also be recompiled! readonly doesn't have this issue.

Best Practice:
- Use const for true constants that NEVER change (PI, days in week)
- Use readonly for values set at runtime or that might change between versions

23 Q23. What is Inheritance? ▼ 
Inheritance allows a class (child/derived) to acquire properties and methods 
of another class (parent/base). It promotes code reusability.

Syntax: class Child : Parent

Example:
// Base class (Parent)
public class Animal
{
    public string Name { get; set; }
    public int Age { get; set; }
    
    public void Eat()
    {
        Console.WriteLine($"{Name} is eating");
    }
    
    public void Sleep()
    {
        Console.WriteLine($"{Name} is sleeping");
    }
}

// Derived class (Child)
public class Dog : Animal
{
    public string Breed { get; set; }
    
    public void Bark()
    {
        Console.WriteLine($"{Name} says Woof!");
    }
}

// Usage
Dog dog = new Dog();
dog.Name = "Buddy";     // Inherited from Animal
dog.Age = 3;            // Inherited from Animal
dog.Breed = "Labrador"; // Own property
dog.Eat();              // Inherited method
dog.Bark();             // Own method

Benefits:
- Code reusability (don't rewrite common code)
- Establishes IS-A relationship (Dog IS-A Animal)
- Supports polymorphism
- Easy to extend functionality
24 Q24. What are types of Inheritance? ▼ 
1. SINGLE INHERITANCE:
   One child inherits from one parent.
   
   Animal ? Dog
   
   class Dog : Animal { }

2. MULTILEVEL INHERITANCE:
   Chain of inheritance (grandparent ? parent ? child).
   
   Animal ? Dog ? GoldenRetriever
   
   class Animal { }
   class Dog : Animal { }
   class GoldenRetriever : Dog { }

3. HIERARCHICAL INHERITANCE:
   Multiple children inherit from same parent.
   
   Animal ? Dog
   Animal ? Cat
   Animal ? Bird
   
   class Dog : Animal { }
   class Cat : Animal { }
   class Bird : Animal { }

4. MULTIPLE INHERITANCE (NOT supported with classes in C#):
   One child inherits from multiple parents.
   
   class Child : Parent1, Parent2 { }  // ERROR in C#!
   
   Achieved through INTERFACES:
   class Dog : IAnimal, IPet { }  // OK!

5. HYBRID INHERITANCE:
   Combination of above types.
   Not directly supported in C# (due to diamond problem).
   Achieved through interfaces.

Why C# doesn't support multiple class inheritance:
- Diamond Problem: If both parents have same method, which one to use?
- Complexity and ambiguity
- Interfaces solve this cleanly
25 Q25. Why C# doesn't support Multiple Inheritance? ▼ 
C# doesn't allow a class to inherit from multiple classes due to the 
DIAMOND PROBLEM.

Diamond Problem:
       ClassA
      /      \
   ClassB   ClassC
      \      /
       ClassD

If ClassB and ClassC both override a method from ClassA,
which version does ClassD get? AMBIGUITY!

Example (if it were allowed):
class A
{
    public virtual void Display() => Console.WriteLine("A");
}

{
    public override void Display() => Console.WriteLine("B");
}

class C : A
{
    public override void Display() => Console.WriteLine("C");
}

// If this were allowed:
class D : B, C  // Which Display()? B's or C's? AMBIGUOUS!
{
}

C# Solution: Use INTERFACES
- A class can implement MULTIPLE interfaces
- No ambiguity because interfaces don't have implementation (before C# 8)
- With default interface methods (C# 8+), explicit implementation resolves conflicts

interface ISwimmable { void Swim(); }

class Duck : IFlyable, ISwimmable  // Multiple interfaces - OK!
{

}

30 Q30. What is the difference between IS-A and HAS-A relationship? ▼ 
IS-A (Inheritance):
- Child IS-A type of Parent
- Achieved through inheritance (:)
- "Dog IS-A Animal"
- "Employee IS-A Person"

class Animal { }
class Dog : Animal { }  // Dog IS-A Animal

HAS-A (Composition):
- Class HAS-A reference to another class
- Achieved through containing object as property
- "Car HAS-A Engine"
- "Employee HAS-A Address"

class Engine
{
    public void Start() { }
}

class Car
{
    private Engine _engine;  // Car HAS-A Engine
    
    public Car()
    {
        _engine = new Engine();
    }
    
    public void StartCar()
    {
        _engine.Start();
    }
}

Examples:
IS-A:
- Dog IS-A Animal ?
- Car IS-A Vehicle ?
- Manager IS-A Employee ?

HAS-A:
- Car HAS-A Engine ?
- Employee HAS-A Address ?
- Order HAS-A List<OrderItem> ?

Wrong usage:
- Car IS-A Engine ? (Car is not a type of Engine)
- Dog HAS-A Animal ? (Dog doesn't contain an Animal)
31 Q31. What is Composition vs Inheritance? When to use which? ▼ 
INHERITANCE (IS-A):
class Dog : Animal { }
- Tight coupling between parent and child
- Child depends on parent's implementation
- Changes in parent affect all children
- Cannot change at runtime

COMPOSITION (HAS-A):
class Car
{
    private IEngine _engine;
    public Car(IEngine engine) { _engine = engine; }
}
- Loose coupling
- Can swap implementations at runtime
- More flexible
- Follows "Favor Composition over Inheritance" principle

Example - Inheritance approach (rigid):
class Logger
{
    public void Log(string msg) => Console.WriteLine(msg);
}

class FileLogger : Logger
{
    // Inherits Log, but what if we want both File AND Database?
    // Can't inherit from two classes!
}

Example - Composition approach (flexible):
interface ILogger
{
    void Log(string message);
}

class FileLogger : ILogger
{
    public void Log(string message) => File.AppendAllText("log.txt", message);
}

class DatabaseLogger : ILogger
{
    public void Log(string message) => _db.Logs.Add(new Log { Message = message });
}

class OrderService
{
    private readonly ILogger _logger;  // HAS-A logger
    
    public OrderService(ILogger logger)  // Inject any logger!
    {
        _logger = logger;
    }
}

// Can swap at runtime:
var service1 = new OrderService(new FileLogger());
var service2 = new OrderService(new DatabaseLogger());

When to use Inheritance:
- True IS-A relationship
- Shared behavior that won't change
- Framework requires it (Controller : ControllerBase)

When to use Composition:
- HAS-A relationship
- Need flexibility to swap behavior
- Need multiple behaviors (can't multi-inherit)
- Following SOLID principles
- Most of the time � prefer composition!

32 Q32. What is Polymorphism? ▼ 
Polymorphism means "many forms" � same method/operator behaves differently 
based on the context or object type.

Two types:
1. Compile-time (Static) Polymorphism ? Method Overloading, Operator Overloading
2. Runtime (Dynamic) Polymorphism ? Method Overriding (virtual/override)

Example:
// Same method name "Draw" behaves differently based on object
Shape shape1 = new Circle();
Shape shape2 = new Rectangle();

shape1.Draw();  // Draws a circle
shape2.Draw();  // Draws a rectangle

// Same "+" operator behaves differently
int result = 5 + 3;           // Addition: 8
string text = "Hello" + " ";  // Concatenation: "Hello "

Real-world analogy:
- A person behaves differently as Employee, Father, Husband
- Same person, different behavior based on context
33 Q33. What is Compile-time Polymorphism (Method Overloading)? ▼ 
Compile-time polymorphism is resolved at COMPILE TIME. The compiler decides 
which method to call based on method signature.

Achieved through: Method Overloading, Operator Overloading

public class Calculator
{
    // Same method name, different parameters
    public int Add(int a, int b)
    {
        return a + b;
    }
    
    public double Add(double a, double b)
    {
        return a + b;
    }
    
    public int Add(int a, int b, int c)
    {
        return a + b + c;
    }
    
    public string Add(string a, string b)
    {
        return a + b;
    }
}

var calc = new Calculator();
calc.Add(5, 3);          // Calls int version ? 8
calc.Add(5.5, 3.2);     // Calls double version ? 8.7
calc.Add(1, 2, 3);      // Calls 3-param version ? 6
calc.Add("Hi", " World"); // Calls string version ? "Hi World"

// Compiler knows at compile time which method to call
// Based on number and type of arguments
34 Q34. What is Runtime Polymorphism (Method Overriding)? ▼ 
Runtime polymorphism is resolved at RUNTIME. The actual method called depends 
on the object type, not the reference type.

Achieved through: virtual + override keywords

public class Shape
{
    public virtual double CalculateArea()
    {
        return 0;
    }
}

public class Circle : Shape
{
    public double Radius { get; set; }
    
    public override double CalculateArea()
    {
        return Math.PI * Radius * Radius;
    }
}

public class Rectangle : Shape
{
    public double Width { get; set; }
    public double Height { get; set; }
    
    public override double CalculateArea()
    {
        return Width * Height;
    }
}

// Runtime polymorphism in action:
Shape shape1 = new Circle { Radius = 5 };
Shape shape2 = new Rectangle { Width = 4, Height = 6 };

// Reference type is Shape, but actual method called depends on OBJECT type
Console.WriteLine(shape1.CalculateArea());  // 78.54 (Circle's method)
Console.WriteLine(shape2.CalculateArea());  // 24 (Rectangle's method)

// Powerful with collections:
List<Shape> shapes = new List<Shape>
{
    new Circle { Radius = 3 },
    new Rectangle { Width = 5, Height = 2 },
    new Circle { Radius = 7 }
};

foreach (var shape in shapes)
{
    Console.WriteLine(shape.CalculateArea());  // Correct method called for each!
}
35 Q35. What is Method Overloading? Rules? ▼ 
Method Overloading: Multiple methods with SAME NAME but DIFFERENT parameters 
in the SAME class.

Rules:
- Same method name
- Different parameter list (number, type, or order)
- Return type alone is NOT enough to overload
- Can have different return types (but parameters must differ)
- Can have different access modifiers

Valid overloading:
public class Printer
{
    public void Print(int number) { }           // 1 int param
    public void Print(string text) { }          // 1 string param
    public void Print(int a, int b) { }         // 2 int params
    public void Print(string text, int count) { } // string + int
    public void Print(int count, string text) { } // int + string (order differs)
}

Invalid overloading:
// CANNOT overload by return type only:
public int Calculate(int a, int b) { return a + b; }
public double Calculate(int a, int b) { return a + b; }  // ERROR! Same params

// CANNOT overload by parameter name only:
public void Print(int x) { }
public void Print(int y) { }  // ERROR! Same signature

// ref/out/in count as different:
public void Process(int x) { }
public void Process(ref int x) { }  // Valid! Different signature
// But ref and out cannot overload each other
36 Q36. What is Method Overriding? Rules? ▼ 
Method Overriding: Child class provides its own implementation of a method 
already defined in the parent class.

Rules:
- Method in parent must be virtual, abstract, or override
- Child uses 'override' keyword
- Same method name, same parameters, same return type
- Cannot override static methods
- Cannot override sealed methods
- Access modifier must be the same
- Cannot reduce accessibility

Example:
public class Animal
{
    public virtual string Speak()  // Must be virtual
    {
        return "...";
    }
}

public class Dog : Animal
{
    public override string Speak()  // Must use override
    {
        return "Woof!";
    }
}

public class Cat : Animal
{
    public override string Speak()
    {
        return "Meow!";
    }
}

Animal animal = new Dog();
Console.WriteLine(animal.Speak());  // "Woof!" (runtime polymorphism)

animal = new Cat();
Console.WriteLine(animal.Speak());  // "Meow!"
37 Q37. What is the difference between Overloading vs Overriding? ▼ 
| Feature        | Overloading              | Overriding               |
|----------------|--------------------------|--------------------------|
| Definition     | Same name, diff params   | Same name, same params   |
| Where          | Same class               | Parent-Child classes     |
| Polymorphism   | Compile-time (static)    | Runtime (dynamic)        |
| Keywords       | None needed              | virtual + override       |
| Parameters     | Must be different        | Must be same             |
| Return type    | Can be different         | Must be same             |
| Inheritance    | Not required             | Required                 |
| Purpose        | Multiple versions        | Change parent behavior   |
| Binding        | Early binding            | Late binding             |

Overloading:
class Math
{
    int Add(int a, int b) { }        // Same class
    double Add(double a, double b) { } // Different params
}

Overriding:
class Animal
{
    virtual void Speak() { }  // Parent
}
class Dog : Animal
{
    override void Speak() { }  // Child changes behavior
}

'virtual' keyword marks a method/property in the base class that CAN be 
overridden by derived classes.

Rules:
- Used in base class
- Method has a default implementation
- Derived class MAY override (not required)
- Cannot be used with: static, abstract, private, override

public class Notification

public class EmailNotification : Notification

    public override void Send(string message)

Rules:
- Used in derived class
- Base method must be virtual, abstract, or override
- Same signature (name, params, return type)
- Cannot override non-virtual methods
- Cannot use with: new, static, virtual (on same method)

40 Q40. What is the new keyword (method hiding)? ▼ 
'new' keyword HIDES the parent's method instead of overriding it.
The method called depends on the REFERENCE TYPE, not the object type.

public class Animal
{
    public void Speak()  // NOT virtual
    {
        Console.WriteLine("Animal speaks");
    }
}

public class Dog : Animal
{
    public new void Speak()  // HIDES parent's Speak
    {
        Console.WriteLine("Dog barks");
    }
}

// Behavior:
Dog dog = new Dog();
dog.Speak();  // "Dog barks" (Dog reference ? Dog's method)

Animal animal = new Dog();
animal.Speak();  // "Animal speaks" (Animal reference ? Animal's method!)
// ? This is the KEY difference from override!

Without 'new' keyword, compiler gives a warning but behaves the same way.
'new' explicitly tells compiler "I know I'm hiding, this is intentional."
41 Q41. What is the difference between virtual/override vs new? ▼ 
virtual/override (TRUE polymorphism):
- Method called based on OBJECT type (runtime)
- Parent method is REPLACED

new (method hiding):
- Method called based on REFERENCE type (compile-time)
- Parent method is HIDDEN (still exists)

Example showing the difference:
public class Base
{
    public virtual void Method1()
    {
        Console.WriteLine("Base.Method1");
    }
    
    public void Method2()
    {
        Console.WriteLine("Base.Method2");
    }
}

public class Derived : Base
{
    public override void Method1()  // Override
    {
        Console.WriteLine("Derived.Method1");
    }
    
    public new void Method2()  // Hide
    {
        Console.WriteLine("Derived.Method2");
    }
}

Base obj = new Derived();

obj.Method1();  // "Derived.Method1" ? override: object type wins
obj.Method2();  // "Base.Method2"    ? new: reference type wins

Derived obj2 = new Derived();
obj2.Method1();  // "Derived.Method1"
obj2.Method2();  // "Derived.Method2"

Summary:
| Scenario          | virtual/override    | new (hiding)         |
|-------------------|---------------------|----------------------|
| Base ref = Derived| Derived's method    | Base's method        |
| Derived ref       | Derived's method    | Derived's method     |
| Polymorphism      | YES                 | NO                   |

Best Practice: Use virtual/override for polymorphism. Use 'new' only when 
you intentionally want to break the polymorphic chain (rare).

43 Q43. What is Operator Overloading? ▼ 
Operator Overloading allows you to define custom behavior for operators 
(+, -, *, ==, etc.) for your own classes.

Example:
public class Money
{
    public decimal Amount { get; set; }
    public string Currency { get; set; }
    
    public Money(decimal amount, string currency)
    {
        Amount = amount;
        Currency = currency;
    }
    
    // Overload + operator
    public static Money operator +(Money a, Money b)
    {
        if (a.Currency != b.Currency)
            throw new InvalidOperationException("Cannot add different currencies");
        return new Money(a.Amount + b.Amount, a.Currency);
    }
    
    // Overload - operator
    public static Money operator -(Money a, Money b)
    {
        if (a.Currency != b.Currency)
            throw new InvalidOperationException("Cannot subtract different currencies");
        return new Money(a.Amount - b.Amount, a.Currency);
    }
    
    // Overload == operator
    public static bool operator ==(Money a, Money b)
    {
        return a.Amount == b.Amount && a.Currency == b.Currency;
    }
    
    public static bool operator !=(Money a, Money b)
    {
        return !(a == b);
    }
    
    public override string ToString() => $"{Amount} {Currency}";
}

// Usage:
var price1 = new Money(100, "USD");
var price2 = new Money(50, "USD");
var total = price1 + price2;  // 150 USD
Console.WriteLine(total);     // "150 USD"

Rules:
- Must be public static
- At least one parameter must be the containing type
- Some operators must be overloaded in pairs (== and !=)
- Cannot overload: =, &&, ||, ?:, new, typeof, sizeof
44 Q44. What is Covariance and Contravariance? ▼ 
These allow implicit reference conversion for generic types and delegates.

COVARIANCE (out) - Can use MORE derived type than specified:
- Used with: return types, IEnumerable<out T>
- "Output" position

// IEnumerable<out T> is covariant
IEnumerable<string> strings = new List<string> { "a", "b" };
IEnumerable<object> objects = strings;  // OK! string derives from object

// Covariant interface
interface IProducer<out T>
{
    T Produce();  // T only in output position
}

class AnimalProducer : IProducer<Animal> { public Animal Produce() => new Dog(); }
class DogProducer : IProducer<Dog> { public Dog Produce() => new Dog(); }

IProducer<Animal> producer = new DogProducer();  // OK! Dog is more derived

CONTRAVARIANCE (in) - Can use LESS derived type than specified:
- Used with: input parameters, Action<in T>
- "Input" position

// Action<in T> is contravariant
Action<object> objectAction = obj => Console.WriteLine(obj);
Action<string> stringAction = objectAction;  // OK! object is less derived
stringAction("Hello");

// Contravariant interface
interface IConsumer<in T>
{
    void Consume(T item);  // T only in input position
}

Summary:
- Covariance (out): Child ? Parent direction (more derived to less derived)
- Contravariance (in): Parent ? Child direction (less derived to more derived)
- Invariant: No conversion allowed (default for generic classes)

45 Q45. What is Abstraction? ▼ 
Abstraction means hiding complex implementation details and showing only 
the essential features to the user.

"Show WHAT it does, hide HOW it does it"

Real-world examples:
- ATM: You see buttons (withdraw, deposit), not internal circuits
- Car: You use steering/pedals, not engine internals
- TV Remote: You press buttons, not deal with infrared signals

In C#, achieved through:
1. Abstract classes
2. Interfaces

Example:
// Abstract - defines WHAT, not HOW
public abstract class PaymentProcessor
{

}

// Concrete - defines HOW
public class StripePayment : PaymentProcessor

    {
        // Complex Stripe API integration hidden here

    {
        // Complex refund logic hidden
    }
}

// User only sees: processor.ProcessPayment(100);
// Doesn't need to know Stripe internals
46 Q46. What is an Abstract class? ▼ 
An Abstract class is a class that CANNOT be instantiated and may contain 
abstract methods (without implementation) that derived classes MUST implement.

public abstract class Shape
{
    public string Color { get; set; }
    
    // Abstract method - NO body, MUST be overridden
    public abstract double CalculateArea();
    public abstract double CalculatePerimeter();
    
    // Non-abstract method - HAS body, CAN be used as-is
    public void Display()
    {
        Console.WriteLine($"Shape: {GetType().Name}, Color: {Color}, Area: {CalculateArea()}");
    }
}

public class Circle : Shape
{
    public double Radius { get; set; }
    
    public override double CalculateArea() => Math.PI * Radius * Radius;
    public override double CalculatePerimeter() => 2 * Math.PI * Radius;
}

public class Rectangle : Shape
{
    public double Width { get; set; }
    public double Height { get; set; }
    
    public override double CalculateArea() => Width * Height;
    public override double CalculatePerimeter() => 2 * (Width + Height);
}

// Usage:
// Shape s = new Shape();  // ERROR! Cannot instantiate abstract class
Shape s = new Circle { Radius = 5, Color = "Red" };
s.Display();  // Works! Uses inherited non-abstract method
47 Q47. What is an Abstract method? ▼ 
An Abstract method is a method declared in an abstract class with NO body.
Derived classes MUST provide the implementation.

Rules:
- Can only exist in abstract class
- No method body (just declaration)
- Implicitly virtual (no need to add virtual)
- Derived class MUST override it (unless derived is also abstract)
- Cannot be private (must be accessible to derived class)
- Cannot be static

public abstract class Database
{
    // Abstract methods - derived MUST implement
    public abstract void Connect();
    public abstract void Disconnect();
    public abstract List<T> Query<T>(string sql);
    
    // Non-abstract - shared implementation
    public void LogQuery(string sql)
    {
        Console.WriteLine($"[{DateTime.Now}] Executing: {sql}");
    }
}

public class SqlServerDatabase : Database
{
    public override void Connect() { /* SQL Server connection */ }
    public override void Disconnect() { /* Close SQL connection */ }
    public override List<T> Query<T>(string sql) { /* Execute query */ }
}

public class MongoDatabase : Database
{
    public override void Connect() { /* MongoDB connection */ }
    public override void Disconnect() { /* Close Mongo connection */ }
    public override List<T> Query<T>(string sql) { /* Convert to Mongo query */ }
}
48 Q48. Can an Abstract class have a Constructor? ▼ 
YES! Abstract classes CAN have constructors.

Why? To initialize common fields/properties when derived class is created.

public abstract class Employee
{
    public string Name { get; set; }
    public DateTime HireDate { get; set; }
    
    // Constructor in abstract class
    protected Employee(string name)
    {
        Name = name;
        HireDate = DateTime.Now;
        Console.WriteLine($"Employee created: {name}");
    }
    
    public abstract decimal CalculateSalary();
}

public class FullTimeEmployee : Employee
{
    public decimal MonthlySalary { get; set; }
    
    public FullTimeEmployee(string name, decimal salary) : base(name)
    {
        MonthlySalary = salary;
    }
    
    public override decimal CalculateSalary() => MonthlySalary;
}

// Cannot do: new Employee("John");  // ERROR!
// But constructor runs when creating derived:
var emp = new FullTimeEmployee("John", 5000);
// Output: "Employee created: John"

Key points:
- Abstract class constructor is called via 'base()' from derived class
- Usually marked protected (not public, since can't instantiate directly)
- Used to enforce initialization of common properties
49 Q49. Can an Abstract class have non-abstract methods? ▼ 
YES! Abstract classes can have BOTH abstract and non-abstract methods.

This is one of the KEY differences from interfaces (before C# 8).

public abstract class Report
{
    // Abstract - derived MUST implement
    public abstract string GenerateContent();
    public abstract string GetTitle();
    
    // Non-abstract - shared implementation (derived CAN use as-is)
    public void Print()
    {
        Console.WriteLine($"=== {GetTitle()} ===");
        Console.WriteLine(GenerateContent());
        Console.WriteLine("===================");
    }
    
    public void SaveToFile(string path)
    {
        File.WriteAllText(path, GenerateContent());
    }
    
    // Virtual - derived CAN override (optional)
    public virtual string GetFooter()
    {
        return $"Generated on {DateTime.Now}";
    }
}

public class SalesReport : Report
{
    public override string GenerateContent() => "Sales data...";
    public override string GetTitle() => "Monthly Sales Report";
    // Print() and SaveToFile() inherited as-is
    // GetFooter() can be overridden or used as-is
}

This is the Template Method Pattern:
- Abstract class defines the skeleton (template)
- Some steps are fixed (non-abstract)
- Some steps are customizable (abstract/virtual)
50 Q50. What is the difference between Abstract class and Interface? ▼ 
| Feature              | Abstract Class         | Interface              |
|----------------------|------------------------|------------------------|
| Instantiation        | Cannot                 | Cannot                 |
| Methods              | Abstract + Concrete    | Only abstract (pre C#8)|
| Fields               | Can have               | Cannot have            |
| Constructor          | Can have               | Cannot have            |
| Access modifiers     | Any                    | Public (implicit)      |
| Inheritance          | Single only            | Multiple               |
| State                | Can maintain state     | Cannot (no fields)     |
| Default impl.       | Yes                    | Yes (C# 8+ only)      |

| Keyword              | abstract class         | interface              |

Abstract class: "What something IS" + shared behavior
Interface: "What something CAN DO" (contract/capability)
51 Q51. When to use Abstract class vs Interface? ▼ 
USE ABSTRACT CLASS when:
- Classes share common code (not just contract)
- Need fields/state
- Need constructors
- Need access modifiers on members
- IS-A relationship exists
- Want to provide default behavior

Example: All employees share salary calculation base logic
public abstract class Employee
{
    protected decimal BaseSalary;
    public abstract decimal CalculateBonus();
    public decimal GetTotalPay() => BaseSalary + CalculateBonus();
}

USE INTERFACE when:
- Define a contract/capability
- Need multiple inheritance
- Unrelated classes share behavior
- CAN-DO relationship
- Want loose coupling (DI)
- Different class hierarchies need same behavior

Example: Both Printer and EmailService can "send output"
interface IPrintable { void Print(); }
interface IExportable { void Export(); }

class Invoice : IPrintable, IExportable { }
class Report : IPrintable { }

RULE OF THUMB:
- If you have shared CODE ? Abstract class
- If you have shared CONTRACT ? Interface
- When in doubt ? Interface (more flexible)
52 Q52. Can we create an instance of Abstract class? ▼ 
NO. You cannot create an instance of an abstract class directly.

// COMPILE ERROR:
Shape shape = new Shape();  // Cannot create instance of abstract type

But you CAN:
1. Create instance of derived class:
   Shape shape = new Circle();  // OK!

2. Use as reference type (polymorphism):
   Shape shape = new Rectangle();

3. Use in arrays/collections:
   List<Shape> shapes = new List<Shape>

       new Circle { Radius = 5 },

- Abstract class may have abstract methods with NO body
- If instantiated, calling abstract method would have no code to execute
- It's a blueprint for derived classes, not a complete class

54 Q54. What is an Interface? ▼ 
An Interface is a contract that defines WHAT a class must do, without 
specifying HOW. It contains method signatures, properties, events, and indexers.

public interface IVehicle
{
    // Properties
    string Make { get; set; }
    int Speed { get; }
    
    // Methods
    void Start();
    void Stop();
    void Accelerate(int amount);
}

public class Car : IVehicle
{
    public string Make { get; set; }
    public int Speed { get; private set; }
    
    public void Start() => Console.WriteLine("Car started");
    public void Stop() { Speed = 0; Console.WriteLine("Car stopped"); }
    public void Accelerate(int amount) => Speed += amount;
}

public class Bicycle : IVehicle
{
    public string Make { get; set; }
    public int Speed { get; private set; }
    
    public void Start() => Console.WriteLine("Pedaling");
    public void Stop() { Speed = 0; }
    public void Accelerate(int amount) => Speed += amount / 2;
}

// Polymorphism through interface:
IVehicle vehicle = new Car();

vehicle = new Bicycle();

- Cannot instantiate interface
- Class MUST implement ALL members
- Supports multiple implementation
- Naming convention: prefix with 'I' (IDisposable, IEnumerable)

58 Q58. What is the difference between Interface and Abstract class? (detailed) ▼ 
ABSTRACT CLASS:
- Can have fields (state)
- Can have constructors
- Can have access modifiers (private, protected)
- Single inheritance only
- Can have fully implemented methods
- Can have static members
- Represents IS-A relationship
- Used for closely related classes

- Cannot have fields (no state)
- Cannot have constructors
- All members implicitly public
- Multiple implementation
- Only declarations (before C# 8)
- Cannot have static members (before C# 8)
- Represents CAN-DO relationship
- Used for unrelated classes sharing behavior

// Duck CAN Swim (interface)

DI uses interfaces to inject dependencies, enabling loose coupling and testability.

WITHOUT DI (tight coupling):
public class OrderService

63 Q63. What is IDisposable interface? ▼ 
IDisposable provides a mechanism to release unmanaged resources deterministically.

public interface IDisposable
{
    void Dispose();
}

Implementation:
public class DatabaseConnection : IDisposable
{
    private SqlConnection _connection;
    private bool _disposed = false;
    
    public DatabaseConnection(string connectionString)
    {
        _connection = new SqlConnection(connectionString);
        _connection.Open();
    }
    
    public void Dispose()
    {
        if (!_disposed)
        {
            _connection?.Close();
            _connection?.Dispose();
            _disposed = true;
        }
        GC.SuppressFinalize(this);
    }
}

// Usage with 'using' statement (auto-calls Dispose):
using (var db = new DatabaseConnection("connStr"))
{
    // Use db
}  // Dispose() called automatically here

// C# 8 using declaration:
using var db = new DatabaseConnection("connStr");
// Dispose called at end of scope

When to implement IDisposable:
- Database connections
- File handles
- Network streams
- Unmanaged resources (COM objects, native handles)
64 Q64. What is IEnumerable vs ICollection vs IList? ▼ 
IEnumerable<T> (most basic):
- Forward-only iteration
- Read-only
- Supports foreach
- Deferred execution (LINQ)
- No Count, no Add/Remove

ICollection<T> (extends IEnumerable):
- Count property
- Add, Remove, Clear
- Contains method
- IsReadOnly property

IList<T> (extends ICollection):
- Index-based access [i]
- Insert at position
- RemoveAt(index)
- IndexOf

Hierarchy: IEnumerable<T> ? ICollection<T> ? IList<T>

| Feature      | IEnumerable<T> | ICollection<T> | IList<T>     |
|--------------|----------------|----------------|--------------|
| foreach      | YES            | YES            | YES          |
| Count        | NO             | YES            | YES          |
| Add/Remove   | NO             | YES            | YES          |
| Index [i]    | NO             | NO             | YES          |
| Insert       | NO             | NO             | YES          |
| LINQ         | YES            | YES            | YES          |

Best practice - use the LEAST specific type needed:
public IEnumerable<Product> GetAll() { }     // Just iteration
public ICollection<Product> GetActive() { }  // Need count
public IList<Product> GetPaged() { }         // Need indexing
65 Q65. What is IComparable vs IComparer? ▼ 
IComparable<T> - Object compares ITSELF to another:
public class Employee : IComparable<Employee>
{
    public string Name { get; set; }
    public decimal Salary { get; set; }
    
    // Default comparison (by Salary)
    public int CompareTo(Employee other)
    {
        return Salary.CompareTo(other.Salary);
    }
}

var employees = new List<Employee> { ... };
employees.Sort();  // Uses CompareTo (sorts by Salary)

IComparer<T> - External class compares two objects:
public class NameComparer : IComparer<Employee>
{
    public int Compare(Employee x, Employee y)
    {
        return string.Compare(x.Name, y.Name);
    }
}

public class SalaryDescComparer : IComparer<Employee>
{
    public int Compare(Employee x, Employee y)
    {
        return y.Salary.CompareTo(x.Salary);  // Descending
    }
}

// Usage:
employees.Sort(new NameComparer());        // Sort by name
employees.Sort(new SalaryDescComparer());  // Sort by salary desc

Difference:
- IComparable: ONE default sort (built into the class)
- IComparer: MULTIPLE sort strategies (external, reusable)

Return values:
- Negative: x comes before y
- Zero: x equals y
- Positive: x comes after y

68 Q68. What is the difference between static and non-static? ▼ 
| Feature        | Static                   | Non-Static (Instance)    |
|----------------|--------------------------|--------------------------|
| Belongs to     | Class/Type               | Object/Instance          |
| Access         | ClassName.Member         | object.Member            |
| Memory         | One copy (shared)        | Per object copy          |
| Keyword        | static                   | No keyword               |
| 'this'         | Cannot use               | Can use                  |
| Created        | When class loads         | When object created      |
| Use case       | Utility, shared data     | Object-specific data     |

Example:
public class BankAccount
{
    // Static - shared across ALL accounts
    public static decimal InterestRate = 0.05m;
    public static int TotalAccounts = 0;
    
    // Non-static - unique per account
    public string Owner { get; set; }
    public decimal Balance { get; set; }
    
    public BankAccount(string owner)
    {
        Owner = owner;
        TotalAccounts++;  // Static accessed from instance
    }
    
    // Static method
    public static void SetInterestRate(decimal rate)
    {
        InterestRate = rate;
        // Cannot access Owner or Balance here (no instance)
    }
    
    // Instance method
    public decimal CalculateInterest()
    {
        return Balance * InterestRate;  // Can access both static and instance
    }
}
69 Q69. What is an Extension Method? ▼ 
Extension Methods add new methods to existing types WITHOUT modifying them.

Rules:
- Must be in a static class
- Must be a static method
- First parameter uses 'this' keyword + the type being extended

public static class StringExtensions
{
    public static bool IsNullOrEmpty(this string str)
    {
        return string.IsNullOrEmpty(str);
    }
    
    public static string Capitalize(this string str)
    {
        if (string.IsNullOrEmpty(str)) return str;
        return char.ToUpper(str[0]) + str.Substring(1).ToLower();
    }
    
    public static int WordCount(this string str)
    {
        return str.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;
    }
}

// Usage (looks like instance method):
string name = "hello world";
bool empty = name.IsNullOrEmpty();    // false
string cap = name.Capitalize();       // "Hello world"
int words = name.WordCount();         // 2

// LINQ is built entirely on extension methods:
var result = numbers.Where(n => n > 5).OrderBy(n => n).ToList();
// Where, OrderBy, ToList are all extension methods on IEnumerable<T>

Common use cases:
- Adding utility methods to built-in types
- LINQ methods
- Fluent APIs
- Adding methods to interfaces
70 Q70. What is a Generic class/method? ▼ 
Generics allow writing type-safe code that works with ANY type, 
determined at compile time.

Generic Method:
public T GetMax<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) > 0 ? a : b;
}

int maxInt = GetMax(5, 10);           // T = int
string maxStr = GetMax("abc", "xyz"); // T = string

Generic Class:
public class Repository<T> where T : class
{
    private List<T> _items = new List<T>();
    
    public void Add(T item) => _items.Add(item);
    public T GetById(int index) => _items[index];
    public IEnumerable<T> GetAll() => _items;
    public int Count => _items.Count;
}

// Usage with different types:
var productRepo = new Repository<Product>();
productRepo.Add(new Product { Name = "Phone" });

var employeeRepo = new Repository<Employee>();
employeeRepo.Add(new Employee { Name = "John" });

Benefits:
- Type safety (compile-time checking)
- No boxing/unboxing (performance)
- Code reusability (one class works for all types)
- No type casting needed

{
    private IntPtr _nativeResource;  // Unmanaged
    private Stream _managedResource; // Managed
    private bool _disposed = false;
    
    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);  // Skip finalizer
    }
    
    protected virtual void Dispose(bool disposing)
    {
        if (!_disposed)
        {
            if (disposing)
            {
                // Release MANAGED resources
                _managedResource?.Dispose();
            }
            
            // Release UNMANAGED resources
            CloseHandle(_nativeResource);
            _nativeResource = IntPtr.Zero;
            
            _disposed = true;
        }
    }
    
    ~ResourceHolder()  // Finalizer (safety net)
    {
        Dispose(false);  // Only unmanaged cleanup
    }
}

            yield return i;  // Returns one item, pauses here
    }
}

// Usage - items generated on demand:
foreach (int num in GetEvenNumbers(10))
{
    Console.WriteLine(num);  // 0, 2, 4, 6, 8, 10
    if (num == 6) break;     // Stops early - remaining never generated!
}

yield break - stops iteration:
public static IEnumerable<int> GetNumbers()
{
    yield return 1;
    yield return 2;
    yield return 3;
    yield break;      // Stops here
    yield return 4;   // Never reached
}

Benefits:
- Lazy evaluation (compute only what's needed)
- Memory efficient (doesn't store all items)
- Can represent infinite sequences
- Deferred execution

// Infinite sequence (possible with yield):
public static IEnumerable<int> Fibonacci()
{
    int a = 0, b = 1;
    while (true)
    {
        yield return a;
        (a, b) = (b, a + b);
    }
}

// Take only what you need:
var first10 = Fibonacci().Take(10).ToList();
117 Q103. What is LINQ? ▼ 
LINQ (Language Integrated Query) provides a unified syntax to query data 
from different sources (collections, databases, XML).

Two syntaxes:

Query Syntax (SQL-like):
var result = from p in products
             where p.Price > 100
             orderby p.Name
             select new { p.Name, p.Price };

Method Syntax (fluent/lambda):
var result = products
    .Where(p => p.Price > 100)
    .OrderBy(p => p.Name)
    .Select(p => new { p.Name, p.Price });

// Both produce same result. Method syntax is more common.

LINQ works with:
- LINQ to Objects: In-memory collections
- LINQ to Entities: EF Core (database)
- LINQ to XML: XML documents

Key characteristics:
- Deferred execution (query runs when iterated)
- Strongly typed (compile-time checking)
- IntelliSense support
- Composable (chain multiple operations)

Deferred vs Immediate execution:
// Deferred (query not executed yet)
var query = products.Where(p => p.Price > 100);

// Immediate (forces execution NOW)
var list = products.Where(p => p.Price > 100).ToList();
var count = products.Count(p => p.Price > 100);
var first = products.First(p => p.Price > 100);
118 Q104. What are common LINQ methods? ▼ 
FILTERING:
.Where(x => x.Age > 18)              // Filter by condition
.OfType<Dog>()                        // Filter by type

PROJECTION:
.Select(x => x.Name)                  // Transform/map
.SelectMany(x => x.Orders)            // Flatten nested collections

ORDERING:
.OrderBy(x => x.Name)                 // Ascending
.OrderByDescending(x => x.Price)      // Descending
.ThenBy(x => x.LastName)              // Secondary sort

AGGREGATION:
.Count()                               // Total count
.Sum(x => x.Price)                     // Sum
.Average(x => x.Age)                   // Average
.Min(x => x.Price)                     // Minimum
.Max(x => x.Price)                     // Maximum

ELEMENT:
.First(x => x.Id == 5)                // First match (throws if none)
.FirstOrDefault(x => x.Id == 5)       // First or null/default
.Single(x => x.Id == 5)               // Exactly one (throws if 0 or 2+)
.SingleOrDefault(x => x.Id == 5)      // One or null
.Last()                                // Last element
.ElementAt(3)                          // By index

QUANTIFIERS:
.Any(x => x.Price > 1000)             // At least one matches?
.All(x => x.IsActive)                 // All match?
.Contains(item)                        // Contains specific item?

SET OPERATIONS:
.Distinct()                            // Remove duplicates
.Union(otherList)                      // Combine (no duplicates)
.Intersect(otherList)                  // Common elements
.Except(otherList)                     // In first but not second

PARTITIONING:
.Take(10)                              // First N items
.Skip(20)                              // Skip N items
.Take(10).Skip(20)                     // Pagination!

GROUPING:
.GroupBy(x => x.Category)             // Group by key

JOINING:
.Join(orders, p => p.Id, o => o.ProductId, (p, o) => new { p.Name, o.Quantity })

CONVERSION:
.ToList()                              // To List<T>
.ToArray()                             // To T[]
.ToDictionary(x => x.Id)              // To Dictionary
.AsEnumerable()                        // To IEnumerable
.AsQueryable()                         // To IQueryable
