C# Quick Reference

Data Types

Value Types (Stack)int, float, double, bool, char, struct, enum
Reference Types (Heap)string, class, array, delegate, interface, object

Access Modifiers

publicAccessible everywhere
privateSame class only
protectedSame class + derived classes
internalSame assembly only

Key Differences

String vs StringBuilder: String immutable (new object each change) | StringBuilder mutable (same object)
== vs .Equals(): == compares reference (default) | .Equals() compares value
ref vs out: ref must be initialized before | out must be assigned inside method
const vs readonly: const = compile-time, static | readonly = runtime, can set in constructor
IEnumerable vs IQueryable: IEnumerable = in-memory | IQueryable = translates to SQL
abstract vs virtual: abstract = no body, must override | virtual = has body, can override
sealed: Prevents class inheritance or method overriding
async/await: Non-blocking async operations. Returns Task/Task<T>

SQL Quick Reference

Execution Order

Order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

JOINs

INNER JOINOnly matching rows
LEFT JOINAll left + matching right
RIGHT JOINAll right + matching left
FULL JOINAll from both tables

Key Concepts

WHERE vs HAVING: WHERE filters rows before GROUP BY | HAVING filters after GROUP BY
DELETE vs TRUNCATE: DELETE = logged, rollback, triggers | TRUNCATE = minimal log, faster, resets identity
ROW_NUMBER: Unique numbers | RANK: Skips on tie | DENSE_RANK: No skip
Clustered Index: 1 per table, sorts data physically (PK)
Non-Clustered: Multiple allowed, separate pointer structure
UNION: Removes duplicates | UNION ALL: Keeps duplicates (faster)
Primary Key: Unique + NOT NULL | Unique Key: Unique + allows one NULL
CTE: WITH cte AS (query) — temporary named result set

OOPs Quick Reference

4 Pillars

EncapsulationHide data using access modifiers + properties
InheritanceChild class reuses parent class code
PolymorphismSame method, different behavior
AbstractionShow only essential, hide complexity

Key Concepts

Overloading: Same name, different parameters (compile-time)
Overriding: Child redefines parent's virtual method (runtime)
Abstract class: Can't instantiate, can have implementation, single inheritance
Interface: Contract only (C#8+ allows default impl), multiple inheritance
Constructor: Called when object created. Can be overloaded. No return type
this: Current instance | base: Parent class reference

SOLID Principles

S — Single Responsibility: One class = one job = one reason to change
O — Open/Closed: Open for extension, closed for modification
L — Liskov Substitution: Child can replace parent without breaking
I — Interface Segregation: Many small interfaces > one fat interface
D — Dependency Inversion: Depend on abstractions, not concrete classes

Quick Examples

SRP Bad: Employee class handles salary + reports + DB save
SRP Good: EmployeeService, EmployeeRepo, ReportGenerator (separate)
DIP Bad: OrderService creates new SqlRepository() inside
DIP Good: OrderService takes IRepository in constructor (DI)

ASP.NET Core Quick Reference

Middleware order: Exception → HTTPS → Static Files → Routing → Auth → Authorization → Endpoints
Transient: New instance every injection
Scoped: One per HTTP request (use for DbContext)
Singleton: One for entire app lifetime
Program.cs: Entry point. Configure services + middleware pipeline
appsettings.json: Configuration file (connection strings, settings)
[Authorize]: Requires authentication | [AllowAnonymous]: Bypasses auth
Model Binding: Auto-maps request data (query, body, route) to action parameters
Filters: Authorization → Resource → Action → Exception → Result

EF Core Quick Reference

Code-First: C# classes → Database (migrations)
Database-First: Database → C# classes (Scaffold-DbContext)
DbContext: Main class to interact with DB. Contains DbSet<T>
Add-Migration: Creates migration file from model changes
Update-Database: Applies pending migrations to DB
Lazy Loading: Related data loaded when accessed (virtual + proxies)
Eager Loading: .Include() — loads related data upfront
Explicit Loading: .Entry().Collection().Load() — manual loading
AsNoTracking(): Read-only queries, better performance
SaveChanges(): Commits all tracked changes to DB in one transaction

Git Quick Reference

Common Commands

git init: Initialize new repo
git clone [url]: Clone remote repo
git add . : Stage all changes
git commit -m "msg": Commit staged changes
git push: Push to remote
git pull: Fetch + merge from remote
git branch [name]: Create branch
git checkout [branch]: Switch branch
git merge [branch]: Merge branch into current
git stash: Save uncommitted changes temporarily

Key Differences

fetch vs pull: fetch downloads only | pull = fetch + merge
merge vs rebase: merge creates merge commit | rebase replays commits linearly
reset vs revert: reset removes commits | revert creates new undo commit

LINQ Quick Reference

Most Used Methods

Where(x => condition): Filter elements
Select(x => transform): Project/transform elements
OrderBy() / OrderByDescending(): Sort
GroupBy(x => x.Key): Group elements
First() / FirstOrDefault(): Get first element
Single() / SingleOrDefault(): Expect exactly one
Any(x => condition): Returns true if any match
All(x => condition): Returns true if all match
Count() / Sum() / Average() / Max() / Min(): Aggregates
Distinct(): Remove duplicates
Take(n) / Skip(n): Pagination
Join(): Join two collections
SelectMany(): Flatten nested collections
ToList() / ToArray() / ToDictionary(): Materialize query
